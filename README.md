# 🛡️ SharePoint and sandbox compatibility

Some SharePoint and Teams previews render HTML inside a sandboxed `about:srcdoc` iframe.

In that environment:

- The document may have a `null` origin.
- `localStorage` may be unavailable.
- `history.replaceState()` may be blocked.
- Clipboard access may be restricted.
- Print behavior may be controlled by the host.
- Browser behavior may differ from opening the HTML directly.

The sandbox-fixed version guards optional browser operations with origin checks and error handling.

## Expected behavior in a restricted preview

| Capability | Expected behavior |
|---|---|
| Tabs | Continues to work |
| Keyboard navigation | Continues to work |
| Search and filters | Continues to work |
| Dark-mode toggle | Works for the current preview session |
| Dark-mode persistence | May be unavailable |
| URL hash updates | Skipped when the page has a null origin |
| Copy buttons | Attempt the action and display fallback feedback when blocked |
| Printing | Depends on the preview host’s permissions |

> ✅ A blocked optional browser feature should not stop the rest of the dashboard.

## Sandbox-safe storage pattern

```javascript
function safeStorageGet(key) {
  try {
    return window.localStorage.getItem(key);
  } catch (error) {
    return null;
  }
}

function safeStorageSet(key, value) {
  try {
    window.localStorage.setItem(key, value);
    return true;
  } catch (error) {
    return false;
  }
}
```

## Sandbox-safe history pattern

```javascript
function safeReplaceHash(id) {
  try {
    if (
      window.location.origin !== "null" &&
      window.location.hash.slice(1) !== id
    ) {
      window.history.replaceState(null, "", `#${id}`);
    }
  } catch (error) {
    // The host preview controls navigation in restricted sandboxes.
  }
}
```

# 🧯 Troubleshooting

## 🚨 SecurityError involving localStorage

### Cause

The HTML is being previewed in a sandbox without same-origin permission.

### Resolution

Use the sandbox-fixed release.

The fixed version catches storage errors and continues without theme persistence.

---

## 🚨 SecurityError involving history.replaceState

### Cause

A preview with a null origin cannot create a history state for the requested section URL.

### Resolution

The sandbox-fixed version checks the document origin and skips history updates when the origin is null.

The selected tab should still open normally.

---

## 📋 Copy button reports a failure

### Cause

The host, browser permission, or security context may block clipboard access.

### Resolution

Select and copy the visible request text manually, or open the page through an approved hosted location that permits clipboard access.

---

## 🌙 Dark mode does not stay selected

### Cause

Browser storage is unavailable in the current preview.

### Resolution

Dark mode should still apply during the current session.

Open the application directly or through a normal hosted origin if persistent theme selection is required.

---

## 🔗 A section does not update the address bar

### Cause

Hash history updates are intentionally disabled in a null-origin sandbox.

### Resolution

The tab should still open.

Address-bar synchronization resumes when the application is served through a normal origin.

---

## 📱 A table is wider than the screen

### Cause

The software and learning tables contain several columns.

### Resolution

Scroll horizontally inside the table container.

This is expected responsive behavior.

---

## 🎨 The page looks different when printed

### Cause

Print styling removes navigation and interactive controls, reveals all sections, and reduces decorative styling.

### Resolution

This is intentional so the printed or PDF version works as a comprehensive review document.

## Add a software item

```html
<tr>
  <td>Software or package</td>
  <td>Category</td>
  <td class="priority">Priority</td>
  <td>Business or technical purpose</td>
</tr>
```

Use an existing category and priority label so the filters continue to work.

## Add a navigation tab

A new tab requires:

1. A tab button with a unique ID
2. An `aria-controls` value
3. A panel with a matching ID
4. An `aria-labelledby` value that points back to the tab

Example:

```html
<button
  id="tab-example"
  class="tab"
  role="tab"
  aria-controls="example"
  aria-selected="false"
  tabindex="-1"
>
  Example
</button>

<section
  id="example"
  class="section"
  role="tabpanel"
  aria-labelledby="tab-example"
  tabindex="0"
  hidden
>
  <h2>Example</h2>
</section>
```

The current JavaScript automatically discovers tabs and panels through their ARIA roles.

## Change application colors

Update CSS custom properties instead of editing each component individually.

After changing a color, test:

- Light mode

- Hover states
